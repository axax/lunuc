# AGENTS.md

Guidance for AI coding agents (Claude, Codex, Cursor, …) working in this repository.
Loaded into every agent session — keep it short and current.

## What this is

**lunuc** is a full-stack framework/CMS for progressive web apps:
Node.js + Express, GraphQL API, MongoDB, React/Preact client (MUI in admin), Webpack, Jest.
Most features live in **extensions** that plug into core via a **hook system**.
Much of the site-specific logic (CMS pages, cronjobs, hooks, APIs) lives **in the database** and is mirrored as files under `dbscripts/`.

## Repository map

| Path | Purpose |
|------|---------|
| `api/` | GraphQL API server. Entry `api/index.mjs` / `index.cjs` → `server.mjs`. Core `schema/` + `resolver/` (User, KeyValue, System, …). `resolver/generic/` = generic CRUD for types. |
| `server/` | Web/SSR server that serves the client (`server/index.mjs`). |
| `client/` | React client: `components/`, `containers/`, `store/`, `middleware/`, `util/`. |
| `extensions/<name>/` | Feature modules (cms, media, post, shop, mailclient, bot, …). See below. |
| `util/` | Shared helpers for api, server and client (`hook.cjs`, `hookAsync.mjs`, `i18n.mjs`, `config.mjs`, `deepMerge.mjs`, …). |
| `dbscripts/` | File mirror of DB content (CmsPages, CronJobs, Hooks, Apis) + impex data imports. Gitignored, per host. See below. |
| `gensrc/` | **Generated** by `webpack.gensrc.js` (config, extension manifests, schema). Never edit by hand. |
| `test/` | Jest tests: `unit/`, `api/`. |
| `shell/` | Install/start scripts for Ubuntu/systemd deployments. |
| `buildconfig.json` | Default build config: active extensions, options, UI icons. Overridden by `/etc/lunuc/buildconfig.json` on servers. |
| `doc.md` | Framework docs: type definitions, field properties, hooks, CMS data resolver. **Read it before touching types or hooks.** |

## Extensions

Typical layout (not every file is required):

```
extensions/<name>/
├── extension.json     # name, description, lazyLoad, dependencies
├── build.json         # type definitions (→ MongoDB collections + generated GraphQL/CRUD), see doc.md
├── server.mjs         # API side: registers schema/resolver/indexes via Hook.on(...)
├── root-server.mjs    # optional: hooks into the web server (server/)
├── client.js          # client hooks (public)
├── client-admin.js    # client hooks (admin UI: menu entries, routes, form fields)
├── schema/index.mjs   # GraphQL SDL as template string
├── resolver/index.mjs # export default db => ({Query: {...}, Mutation: {...}})
├── components/, containers/, translations/, util/, constants/
```

- Activation: `buildconfig.json` → `extensions.<name>.active`. Generated manifests land in `gensrc/`.
- Server registration pattern (see `extensions/post/server.mjs`):
  ```js
  Hook.on('resolver', ({db, resolvers}) => deepMergeToFirst(resolvers, resolver(db)))
  Hook.on('schema', ({schemas}) => schemas.push(schema))
  Hook.on('index', ({db}) => { /* create mongodb indexes */ })
  ```
- Prefer declaring data types in `build.json` (generic resolver is generated) over hand-written schema/resolvers.
- Use `GenericResolver` (`api/resolver/generic/genericResolver.mjs`) for list/CRUD queries.
- Access control: `Util.checkIfUserIsLoggedIn(context)` / `Util.hasCapability` in resolvers and admin UI.
- Smallest extension to copy from: `extensions/post`.

## Hooks

`Hook.on('Name', fn)` / `Hook.call(...)` from `util/hook.cjs` (async variant `util/hookAsync.mjs`).
`Hook.on('Name.key', fn)` registers only once per key. Full list of client and server hooks in `doc.md`
(e.g. `Routes`, `MenuMenu`, `TypeCreateEdit`, `appready`, `typeUpdated_<Type>`, `typeBeforeCreate`).

## dbscripts/ (DB content as files)

The database is the source of truth; `dbscripts/` is a two-way file mirror so content can be edited with normal tools.
Gitignored — each host has its own copy (synced locally via rsync from `/opt/lunuc/dbscripts/`).

| Folder | Type | One folder per entry, containing |
|---|---|---|
| `cmspages/<slug>/` | CmsPage | `page.json` (all attributes, required), `template.json` (JsonDom), `style.css`, `script.js` (client), `serverScript.js`, `dataResolver.json`, `resources.json`, `manual.md` |
| `cronjobs/<name>/` | CronJob | `script.js` / `script.py` + `meta.json` |
| `hooks/<name>/` | Hook | `script.js` + `meta.json` |
| `apis/<slug>/` | Api | `script.js` / `script.py` + `meta.json` |
| `impex/` | — | declarative data imports, see below |

Sync is done by CronJobs (all run with the rights of their creator → create them as admin):
- **`System: export all dbscripts`** — DB → files (impl. `extensions/cms/util/cmsPageFilesServer.mjs`, `api/util/typeScriptFiles.mjs`). Writes `.export-state.json` (field hashes) per folder as baseline. Folder `README.md`s in `cmspages/`, `cronjobs/`, `hooks/`, `apis/` are regenerated by the export.
- **`System: import all dbscripts`** — files → DB, three-way merge per field (file / DB / `.export-state.json`): changed only in file → imported; only in admin → kept; both → conflict, nothing written (`FORCE` = file wins). Supports `DRY_RUN`.

Rules when editing these files:
- Edit only the content files; never edit `.export-state.json`. Don't rename folders — entries are matched by `_id` (`meta.json`) or by the slug in `page.json`, not by folder name.
- A missing file leaves the field unchanged, an empty file clears it. `null` attributes are not set (use `""` to clear text).
- Ids/dates in JSON as `{"$oid": "..."}` / `{"$date": "..."}`. `_id`, `modifiedAt`, `createdBy` in `page.json` are informational.
- New CmsPage: new folder with `page.json` without `_id` → created on import, `_id` written back. New CronJobs/Hooks/Apis are **not** created from files (create them in the admin).
- Secrets (e.g. Api basic-auth passwords) are not exported — don't add them to files.
- Scripts in these entries run inside lunuc (`this.db`, `this.context`, `this.log`, `requireAsync('@api/…' | '@ext/…')`), not as standalone Node.

### dbscripts/impex/ — declarative data import

Inspired by SAP Commerce ImpEx. Impl. `api/util/impex.mjs`, runner CronJob `System: run impex` (source `impex/_setup/run-impex.cronjob.js`).

| Folder | Content |
|---|---|
| `pending/` | files to import, processed alphabetically → prefix `YYYY-MM-DD_NN_` |
| `done/` | successfully imported files + `.log` |
| `scripts/` | files referenced via `$file` (e.g. hook/api scripts) |
| `files/` | optional binaries for `$uploadFile` (Media) |
| `_setup/` | runner cronjob + `transform` helpers |
| `prod/` | complete files for another system (copy into its `pending/`) |

Workflow: file into `pending/` → run with `DRY_RUN = true` → check `pending/<file>.dryrun.log` → run with `DRY_RUN = false`.
On errors the file stays in `pending/` with a `.log`; fix and rerun (`INSERT_UPDATE` is idempotent).

```json
{
  "description": "what this file does",
  "allowRemove": false,
  "operations": [{
    "mode": "INSERT_UPDATE", "type": "GenericData", "definition": "ThalGeschaeftsberichtBereich",
    "key": ["slug"], "replace": [], "defaults": {},
    "items": [{"name": "Gemeindehaushalt", "slug": "gemeindehaushalt", "parent": {"$ref": {"slug": "finanzen-und-jahresrechnungen"}}}]
  }]
}
```

Operation properties:
- `mode`: `INSERT` (error if exists) · `UPDATE` (error if missing) · `INSERT_UPDATE` (default) · `REMOVE` (needs `"allowRemove": true`)
- `type`: collection/type, must be in the cronjob's `ALLOWED_TYPES`. `definition`: GenericData only, name of the `GenericDataDefinition`.
- `key`: fields identifying an existing entry (`GenericDataDefinition` defaults to `name`).
- `replace`: object fields replaced completely; other objects are deep-merged.
- `defaults`: merged into every item. `stringify`: fields stored as JSON string (e.g. `KeyValueGlobal.value`).
- `mergeArray`: `{"value": "name"}` merges into the existing array by `name` (replace/append); `{"name": "x", "$remove": true}` removes.
- `multi` (UPDATE only): update every entry matching `key`; `"key": []` = all entries of type/definition. Without it, multiple matches are an error.
- `transform` (UPDATE only): `{"$file": "../_setup/x.js"}` or inline JS function body, called per entry with `input = {doc, data, values, item}`, returns fields to write or `null` to skip (example `_setup/jb-content-to-elements.js`).
- GenericData shorthand: item without `data` property *is* the data; keys are relative to `data` (`"slug"` = `"data.slug"`).

Special values:
- `{"$ref": {"slug": "x"}}` → `_id` string of the entry with that key (same type/definition); `{"$ref": {"type": "GenericData", "definition": "Other", "slug": "x"}}` for other types; `{"$ref": [{…}, {…}]}` → array; add `"as": "objectId"` for native ObjectId refs. Also resolves entries created earlier in the same file (even in dry run).
- `{"$file": "scripts/hook.js"}` → text of a file (relative to the impex file) · `{"$json": {…}}` → stored as JSON string · `{"$oid"}`, `{"$date"}` → Mongo extended JSON.
- Media: item with `"$uploadFile": "../files/x.jpg"` or `"$uploadBase64": "<base64>"` → file written to the upload folder under the entry's `_id` (skipped if same size exists). Use `"key": ["_id"]` + `"_id": {"$oid": "…"}` to keep source-system ids so references stay valid; `size` is filled from the file.

Writes go through `GenericResolver` (access rights of the cronjob creator, hooks, cache invalidation). Running an impex (also dry run) needs the capability `admin_options` (checked in `runImpex` / `runImpexFile`).
Owner of new entries: user chosen on the page `system/impex`, else `"createdBy": "<username or id>"` on the top level of the file, else the running user. New entries get that user's `createdBy` (+ its `ownerGroup` if the item sets none); existing entries keep their owner. Needs `manage_other_users`.

## Commands

```bash
npm install
npm run start:dev     # api:dev (nodemon, port 3001) + client:dev (webpack serve)
npm run api:dev       # API only
npm run client:dev    # client only
npm run build         # production client build
npm test              # starts temporary mongod on :27018, runs jest, cleans up
npm run lint          # eslint
```

Requires `MONGO_URL` (e.g. `mongodb://localhost:27017/lunuc`).

## Conventions

- **ES modules**: server-side files `.mjs`; `.cjs` only where CommonJS is required (`util/hook.cjs`, `api/index.cjs`). Client files `.js`.
- **Style (eslint)**: single quotes, **no semicolons**, unix line endings, 4-space indent.
- **Language**: code, comments, identifiers and commit messages in English. UI strings via translations (`registerTrs`, `translations/`), languages de/en/fr/it, default `de`.
- Client import aliases: `util/…`, `client/…`, `gen/…` (→ `gensrc/`), defined in `babel.config.json`. In production builds `react`/`react-dom` are aliased to `preact/compat` (`webpack.config.js`).
- Globals: `_app_` (app state, user, config, language) exists on client and in API/SSR — don't introduce new globals.
- Keep changes minimal and local; don't refactor unrelated code.

## Browser support (IE11 must keep working)

The public site must keep running on old browsers, **including Internet Explorer 11**. Keep `main.bundle.js` and all lazy chunks ES5:
- `webpack.config.js`: `target: ['web', 'es5']` — never switch to `es2017`/`es6` (the webpack runtime would start with `(()=>{` → IE11 "Syntax error").
- `babel.config.json` → `env.client_build`: browser targets must contain `"ie 11"` explicitly (`">0.25%"` alone no longer includes IE11 with current browser data).
- `@babel/plugin-transform-runtime` with `"regenerator": true` — with `false` the code needs a global `regeneratorRuntime` and breaks in ES5 mode.
- Prefer plain promises over `async/await` in code that lands in the main bundle (avoids the regenerator runtime, ~7 KB).
- Modern APIs (`Object.assign`, `Promise`, `Map`, `fetch`, …) are polyfilled at runtime (`BASE_POLYFILL` in `index.html`, `/polyfill/more.js` in `client/index.js`); don't rely on APIs without a polyfill or feature check.
- CMS scripts in the database are converted at runtime for old browsers (`legacyjs.js`, `DomUtil.toES5`), not by the build.
- Check after building: every `build/*.bundle.js` must parse as ES5 (e.g. `acorn` with `ecmaVersion: 5`); `serviceworker.js` is not loaded by IE11 and is exempt.

## Do not touch / ignore

- `gensrc/`, `extensions/*/gensrc/` — generated, regenerate via build.
- `dbscripts/**/.export-state.json` — sync baseline, written only by the export.
- `node_modules/`, `build/`, `build_api/`, `backups/`, `projectFilesBackup/`, `uploads/`, `static_private/`, `local_tmp/`, `mongodb_tmp/`, `_neu/`, `neuer ordner/`, `Claude outputs/`.
- `server/*.key`, `*.pem`, `*.crt` — certificates, never read out or modify.
- `index.min.html` — minified build output.

## Gotchas

- Server config is merged from `buildconfig.json` and `/etc/lunuc/buildconfig.json`; behaviour can differ per host (see `hostrules/`, `util/hostrules.mjs`).
- After adding an extension or changing `build.json`, gensrc must be regenerated (webpack build / dev server) before the API sees new types.
- Resolvers receive `db` (native MongoDB driver) — use `ObjectId` from `mongodb` for ids.
- API also renders React server-side (SSR) — avoid browser-only APIs at module top level.
- Editing a file in `dbscripts/` changes nothing until the import cronjob runs on that host.
